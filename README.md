# ragvid

Describe the vibe, get the grade.

```bash
ragvid grade clip.mp4 --vibe "gloomy"
ragvid refine "less blue, more contrast"
ragvid export out.mp4
```

Point it at a video and either a mood word or a reference image. It analyses the
footage, produces a color grade, and lets you talk your way to the look you want.

## Why it works this way

An LLM never sees your frames. It produces **43 numbers** — an [ASC CDL][cdl]
core plus exposure, a shadow/highlight split, six hue qualifiers, a highlight
shoulder and six spatial effects — and everything after that is numpy and
ffmpeg:

```
reference image ──▶ closed-form match ──┐
                                        │      37 colour numbers
                                        ├──▶ GradeSpec ──┬──▶ .cube LUT ──┐
vibe word ────────▶ LLM ────────────────┘      (JSON)    │                ├──▶ ffmpeg
                                            ▲            └──▶ 6 effects ──┘
                                            │                 (filters)
"less blue" ────────────────────────────────┘
```

Two consequences:

- **It's cheap.** One small JSON object per request, so grading a two-hour film
  costs the same as grading a two-second clip.
- **It's refinable.** The `.cube` LUT is a derived artifact, not the source of
  truth. You can't meaningfully adjust a baked LUT; you can adjust numbers.

Analysis samples ~10 frames (not every frame — clips drift, so the median across
samples beats trusting frame 0). Application touches every frame, but that's a
single fast ffmpeg filter with no model in the loop.

The reference-image path uses **no LLM at all** — it's closed-form linear color
transfer — so it works entirely offline.

## Install

```bash
git clone <this repo> && cd rag-video
uv venv && uv pip install -e ".[dev]"
cp .env.example .env    # then add your key
```

Requires `ffmpeg` (with the `lut3d` filter — any recent build has it).

### Providers

| Provider | Env | Notes |
|---|---|---|
| Groq (default) | `GROQ_API_KEY` | Free tier is **8000 tokens/min** — fine interactively, rate-limits under load. Default model `openai/gpt-oss-120b`. |
| Anthropic | `ANTHROPIC_API_KEY` | `RAGVID_PROVIDER=anthropic`. Higher quality baseline. |

> **Rotate your key on first use.** If you were handed a key in a chat or shared
> a `.env`, treat it as compromised — regenerate at the provider console. `.env`
> is gitignored here from the very first commit, but nothing protects a key that
> already leaked.

## Commands

| Command | Does |
|---|---|
| `ragvid grade IN --vibe "..."` | Analyse, plan a grade, write a preview |
| `ragvid grade IN --ref img.jpg` | Same, matched to a reference image (offline) |
| `ragvid refine "..."` | Adjust the current grade conversationally |
| `ragvid spec` | Print the current grade spec as JSON |
| `ragvid reset` | Step back to the previous spec |
| `ragvid export OUT` | Render the full video |

`grade` and `refine` render a 3-frame contact sheet, not the whole file — the
refinement loop stays sub-second. Only `export` does the full render.

## Use it as a library

The CLI is a thin shell over `Project`, which is the whole API. Build a UI
against this — it owns probe, plan, refine, bake, preview and export, so a front
end never reimplements the flow.

```python
from ragvid import Project

p = Project.create("clip.mp4", root="~/grades/clip")
p.plan_from_vibe("gloomy")                              # or plan_from_reference(img)
p.refine("less blue")
p.set_spec(p.spec.model_copy(update={"contrast": 0.4})) # a slider moved
p.undo()
p.export("out.mp4", progress=lambda f: bar.set(f))      # 0.0 -> 1.0
```

Nothing in the core prints, reads argv, calls `sys.exit`, or assumes a working
directory. Failures are typed (`InputError`, `SessionNotFound`, `RateLimited`,
`ProviderNotConfigured`, `FFmpegError`, …) and carry the fields a UI needs to
respond, so nothing has to be recovered by parsing a message.

`python examples/api_tour.py` runs every call in order — no API key needed.
[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) has the layering and the gotchas.

## Layout

```
ragvid/
  project.py      the API — build against this
  spec.py         GradeSpec: the 43 numbers + the math (evaluation order matters)
  probe.py        clip -> ClipStats (sampled frames, median statistics)
  match.py        (source, reference) -> GradeSpec, closed form, no model
  vibe.py         words -> GradeSpec
  refine.py       (GradeSpec, words) -> GradeSpec
  lut.py          GradeSpec -> .cube
  render.py       ffmpeg: previews and exports
  session.py      persistence under <root>/.ragvid/
  errors.py       the typed failures a front end branches on
  cli.py          reference consumer of project.py
  providers/      groq · anthropic
docs/             architecture notes
examples/         runnable API tour
tests/            fixtures generated by conftest.py, no binaries committed
```

## Scope

A grade is **37 colour numbers plus 6 spatial effects**, and the split is not
cosmetic — it is where the `.cube` stops.

- **Colour, baked into the LUT:** gain, lift, gamma (ASC CDL), saturation,
  temperature/tint, contrast, exposure in stops, a shadow/highlight split with
  independent tint and lift, six hue qualifiers, a soft highlight shoulder, and
  a mix of the whole look back toward the source.
- **Effects, applied by ffmpeg around the LUT:** denoise, glow, softness (blur
  or sharpen), grain, vignette, chromatic fringing. A 3D LUT maps one pixel to
  one pixel and cannot see its neighbours, so none of these can live in a
  `.cube` — export them to Resolve and you get the colour and nothing else.
  [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) covers that seam.

Effects are not free, and the bill lands on export. Measured on this repo's
`testsrc2` clip, 1920×1080 at 30fps, 8-core CPU + NVENC, best of three runs:

| Export | Speed |
|---|---|
| colour only (`lut3d` + libx264) | **1.38×** realtime |
| grain + vignette + libx264 | **0.83×** |
| all six effects + libx264 | **0.42×** |
| all six effects + `--gpu` (h264_nvenc) | **0.48×** |

`--gpu` does not rescue that. It swaps the encoder, and the encoder is not the
bottleneck: the same filter chain with *no encode at all* runs at ~0.4×, so
hardware encoding buys about 14% and cannot buy more. Budget roughly 25 minutes
for a 10-minute clip with the full stack, and leave at zero the effects you do
not actually want — two of them cost roughly half of what six do. Per filter at
1080p30, glow (a wide blur plus a blend, 2.8×) is the most expensive effect,
and `lut3d` itself (2.2×) still costs more than any single one of them.

One clip gets one look; for multiple looks, split into clips. Still out of
scope: pacing, cuts, and audio (audio is stream-copied on export, never
re-encoded and never analysed).

[cdl]: https://en.wikipedia.org/wiki/ASC_CDL
